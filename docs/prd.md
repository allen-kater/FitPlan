# FitPlan 产品需求文档（PRD）

## 1. 项目信息

| 字段 | 内容 |
|------|------|
| 产品名称 | FitPlan |
| 语言 | 中文 |
| 技术栈 | 前端：React 18 + TypeScript + Vite 5 + TailwindCSS 3 + MUI；后端：Node.js + Express 4 + TypeScript + Prisma；数据库：SQLite(开发)/PostgreSQL(生产) |
| 项目名 | fitplan |
| 原始需求 | 输入身体数据，自动生成个性化的增肌/减脂饮食方案 + 训练计划。基于好人松松的 Excel 套表计算逻辑，方案生成型产品（非记录型） |

---

## 2. 产品定义

### 2.1 产品目标

| # | 目标 | 衡量指标 |
|---|------|----------|
| G1 | 用户输入身体数据后，一键生成完整的增肌/减脂饮食方案和训练计划 | 方案生成成功率 ≥ 99% |
| G2 | 方案计算逻辑严格基于好人松松 Excel 套表，确保专业性和准确性 | 计算结果与 Excel 套表一致 |
| G3 | 提供持续追踪能力（体重记录、方案调整），让用户能执行并迭代 | 用户7日留存率 ≥ 30% |

### 2.2 用户故事

| # | 角色 | 故事 |
|---|------|------|
| US1 | 健身新手 | As a 健身新手, I want 输入我的身体数据后自动获得饮食方案和训练计划, so that 我不需要自己研究复杂的营养学知识就能开始增肌/减脂 |
| US2 | 有经验的健身者 | As a 有经验的健身者, I want 查看不同训练时段的饮食方案对比, so that 我能选择最适合我作息的方案 |
| US3 | 减脂用户 | As a 减脂用户, I want 记录体重变化并查看趋势, so that 我能判断当前方案是否有效并及时调整 |
| US4 | 增肌用户 | As a 增肌用户, I want 获得精确的宏量营养素配比和食物建议, so that 我能高效增肌而不增加过多脂肪 |
| US5 | 管理员 | As a 管理员, I want 查看用户数据和统计信息, so that 我能了解产品使用情况并优化运营 |

## 4. 详细功能规格

### 4.1 方案生成模块（P0）

#### 4.1.1 用户输入项

| 输入项 | 类型 | 取值范围 | 必填 |
|--------|------|----------|------|
| 性别 | 单选 | 男 / 女 | 是 |
| 身高 | 数字 | 100-250 cm | 是 |
| 体重 | 数字 | 30-300 kg | 是 |
| 年龄 | 数字 | 10-100 岁 | 是 |
| 目标 | 单选 | 增肌 / 减脂 | 是 |
| 力训时间 | 单选 | 7种时段（见下表） | 是 |
| 训练水平 | 单选 | 新手 / 有基础 / 老手 | 是 |
| 有氧习惯 | 组合 | 是否做有氧 + 运动心率 + 静息心率 + 时长 | 减脂时必填 |

**力训时段（7种）：**

| # | 时段名称 | 说明 |
|---|----------|------|
| 1 | 早饭后练-早起版 | 早餐后上午训练 |
| 2 | 早饭后练-晚起版 | 早餐后上午训练（晚起） |
| 3 | 午饭前练 | 午餐前训练 |
| 4 | 午饭后练 | 午餐后训练 |
| 5 | 晚饭前练 | 晚餐前训练 |
| 6 | 晚饭后练 | 晚餐后训练 |
| 7 | 夜里练 | 夜间训练 |

#### 4.1.2 计算逻辑

**Step 1: BMI 计算**

```
BMI = 体重(kg) ÷ 身高(m) ÷ 身高(m)
```

**Step 2: BMR 计算（Mifflin-St Jeor 公式）**

```
男性: BMR = 体重 × 9.99 + 身高 × 6.25 - 年龄 × 4.92 + 5
女性: BMR = 体重 × 9.99 + 身高 × 6.25 - 年龄 × 4.92 - 161
```

**Step 3: 无运动总消耗**

```
无运动总消耗 = BMR ÷ 0.7
```

**Step 4: 力训消耗**

| 训练水平 | 男性消耗 | 女性消耗 |
|----------|----------|----------|
| 新手 | 150 大卡 | 100 大卡 |
| 有基础 | 200 大卡 | 150 大卡 |
| 老手 | 250 大卡 | 200 大卡 |

**Step 5: 有氧消耗**

```
有氧消耗 = (运动心率 ÷ 静息心率 × 6.4 - 6.2) × 体重 × 时长 ÷ 7
```

**Step 6: 每日平衡热量**

```
力训日平衡热量 = 无运动总消耗 + 力训消耗 + 有氧消耗
休息日平衡热量 = 无运动总消耗 + 有氧消耗
```

**Step 7: 目标应吃热量**

```
减脂应吃热量 = 平衡热量 × 0.64
增肌应吃热量 = 平衡热量 × 0.84
```

**Step 8: 宏量营养素分配**

| 营养素 | 计算方式 | 备注 |
|--------|----------|------|
| 蛋白质 | 体重(kg) × 配额(g/kg) | 配额由目标决定 |
| 脂肪 | 男性 60g / 女性 50g | 固定值 |
| 碳水 | (应吃热量 - 蛋白质热量 - 脂肪热量) ÷ 4 | 剩余热量分配 |

#### 4.1.4 方案输出格式

每个方案输出内容：

- **力训日饮食方案**：按餐序（早餐/加餐/午餐/练前/练后/晚餐/夜宵，具体餐序因时段不同）给出每餐的碳水(g)、蛋白质(g)、脂肪(g)克数及食物建议
- **休息日饮食方案**：按餐序给出每餐的碳水(g)、蛋白质(g)、脂肪(g)克数及食物建议
- **运动建议**：力训安排、有氧建议
- **注意事项**：饮食注意事项、训练注意事项、目标切换建议

## 7. 关键业务规则

| 编号 | 规则 | 触发条件 | 处理方式 |
|------|------|----------|----------|
| BR-1 | 减脂→增肌切换建议 | 男性 BMI 22-23 / 女性 BMI 20-21 | 方案中提示"建议转为增肌" |
| BR-2 | 增肌→减脂切换建议 | 男性 BMI 23-24 / 女性 BMI 21-22 | 方案中提示"建议转为减脂" |
| BR-3 | 增肌不做有氧 | 用户目标为增肌 | 隐藏有氧输入项，有氧消耗设为0 |
| BR-4 | 减脂大体重不做有氧 | 减脂且体重 ≥ 80kg | 提示"不建议做有氧"，有氧消耗设为0 |
| BR-5 | 体重变化调整配额 | 体重变化达 10kg | 提示用户重新生成方案 |
| BR-6 | 减重速度参考 | 减脂用户 | 2周减重 2% 为健康速度参考 |
| BR-7 | 增重速度参考 | 增肌用户 | 男性每月 1kg，女性每月 0.5kg |

| 可用性 | 浏览器兼容 | Chrome/Firefox/Safari/Edge 最近2个版本 |
| 可维护性 | 代码规范 | TypeScript 严格模式，ESLint + Prettier |
| 部署 | 数据库策略 | 开发环境 SQLite，生产环境 PostgreSQL |

## 9. UI 设计草案

### 9.1 整体布局

- **导航栏**：顶部固定，Logo + 导航链接 + 用户头像/登录按钮
- **侧边栏**：无（响应式设计，移动端用 hamburger 菜单）
- **主内容区**：居中最大宽度 1200px

### 9.2 关键页面布局

**首页（/）：**
- Hero 区域：产品标语 + "立即制定方案"CTA 按钮
- 功能亮点区：3个核心功能卡片（方案生成/训练计划/科普知识）
- 底部：简要使用流程说明

**创建方案（/plan/create）：**
- 分步表单（Step by Step）：
  - Step 1：基础数据（性别/身高/体重/年龄）
  - Step 2：训练配置（目标/力训时间/训练水平/有氧习惯）
  - Step 3：确认并生成
- 每步有进度指示器
- 根据目标动态显示/隐藏有氧配置

**方案详情（/plan/:id）：**
- 顶部卡片：基础数据摘要 + 计算结果（BMI/BMR/总消耗/应吃热量）
- Tab 切换：力训日 / 休息日
- 每日饮食卡片：按餐序排列，每餐显示碳水/蛋白质/脂肪克数 + 食物建议
- 底部：运动建议 + 注意事项

**个人中心（/profile）：**
- 左侧/上方：身体数据编辑
- 右侧/下方：体重变化折线图（Recharts）
- 体重记录入口：日期选择 + 体重输入
